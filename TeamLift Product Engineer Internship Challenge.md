## **Challenge Objective**

Build a simple scheduling app with a working frontend and backend. We’re evaluating your ability to:

* Build a clean, intuitive user interface  
* Connect the frontend to a backend and data that persists  
* Use AI coding tools effectively to move fast

The goal is for us to see what you are passionate about, where you feel most comfortable, and where you want to push beyond what you already know.

### **The Challenge**

Build a small web app where a person can publish their available time slots and others can book one. The app should let users:

1. Create available time slots (date, start time, duration)  
2. See the list of available slots  
3. Book a slot with their name and email  
4. See that a booked slot is no longer available (no double bookings)

To keep it simple:

* No login or user accounts are needed. Assume a single host who publishes the slots.  
* One time zone is fine.

**Technical expectations**: a React frontend (TypeScript is a plus), a backend with an API and data that persists (any stack is fine, NestJS and PostgreSQL are a plus), and clear instructions on how to run it locally.

**Optional extras** (pick one if you have time, both are welcome but not expected):

1. **Google Calendar:** connect a Google Calendar through the Google Calendar API so slots that clash with existing events are hidden or marked as unavailable.   
2. **AI:** add one simple backend endpoint that calls an LLM. For example, when someone books a slot, generate a short, friendly confirmation message for them. Please use a model with a free tier, such as Gemini through Google AI Studio, so you don’t need to spend anything on credits.

**Tools**  
Use any tools, frameworks, or starter templates you like, including AI coding tools such as Cursor, Claude Code, or Lovable. The only rule is that you understand your code and can explain it in the interview.

**Make It Your Own**  
The brief is a starting point. Feel free to use your imagination and change it or make it a little different, for example a booking page for a tutor’s office hours, a coffee chat scheduler, or a team meeting room planner. We love seeing where candidates take it.

**Deliverables**

1. **A live link to your app.** Hosting it is the best way for us to experience your UI the way a real user would. Vercel, Netlify, or Render work great for the app, and Supabase, Neon, or Render have free databases. If hosting the backend becomes a blocker, a hosted frontend with clear local setup instructions is fine.  
2. **Your GitHub repository** with a short README on how to run it, what you built, which AI tools you used, and what you would improve with more time.   
3. **A short video (optional).** If you feel comfortable, record a quick walkthrough of up to 2 minutes showing your app and the choices you made.

**Evaluation Criteria**

* A clean, intuitive user interface  
* A flow that works end to end  
* Readable, well organized code  
* How you used AI tools to get there  
* The choices you made and where you added your own ideas

**Time Needed**  
The challenge should take about 2 hours. You’re welcome to spend more, but we evaluate with that time in mind, so a focused, working app is better than a big unfinished one. We are not looking for a production-ready product. We want to see how you think, build, and make decisions.

**Submission**  
Once complete, reply to our email (or write to support@teamlift.co) within one week with:

* The live link to your app  
* The link to your GitHub repository  
* Your video link, if you recorded one  
* Subject line: TeamLift Internship Challenge: \[Your Name\]

If you have any questions along the way, just reply to the email and we’ll be happy to help.
